# paddle-meter helper tools

Standalone utilities for working with paddle-meter recordings outside the
Android app. Pure Python 3 (standard library only, no dependencies).

## `paddle_csv.py`

Converts between the compact paddle-meter recording format written by the
firmware and a human-readable CSV, in both directions.

### The paddle-meter format

Recordings (`/data/pm_0001.csv` on the SD card) look like this:

```
# paddle-meter v1 rate=200 arange=4g grange=500dps
t_us,ax,ay,az,gx,gy,gz
1234567,0.1234,-9.8012,0.4321,1.20,-0.50,3.10
...
# samples=41230 dropped=0
```

- `t_us` — microseconds since boot
- `ax,ay,az` — acceleration in m/s²
- `gx,gy,gz` — angular rate in deg/s
- `#` lines are metadata (header + footer)

### Readable format

`to-csv` expands each sample into a row with an index, the timestamp in both
microseconds and seconds, and derived vector magnitudes:

```
# paddle-meter v1 rate=200 arange=4g grange=500dps
# generated by paddle_csv.py to-csv
index,t_us,t_s,ax,ay,az,gx,gy,gz,accel_mag,gyro_mag
0,0,0.000000,0.123400,-9.801200,0.432100,1.200000,-0.500000,3.100000,9.811496,3.361547
...
# samples=5 dropped=0
```

The metadata comments are preserved, so a readable file converts back to a
paddle-meter recording losslessly.

### Usage

```bash
# paddle recording -> readable csv
python3 tools/paddle_csv.py to-csv pm_0001.csv -o pm_0001.readable.csv

# readable csv -> paddle recording (metadata read from the # header)
python3 tools/paddle_csv.py to-paddle pm_0001.readable.csv -o pm_0001.csv

# arbitrary csv with named columns -> paddle recording at 100 Hz
python3 tools/paddle_csv.py to-paddle raw.csv -o pm_0002.csv --rate 100

# auto-detect the direction
python3 tools/paddle_csv.py auto somefile.csv -o out.csv

# stdin/stdout (default output is stdout)
cat pm_0001.csv | python3 tools/paddle_csv.py to-csv > readable.csv
```

### Column matching (`to-paddle`)

Column names are matched case-insensitively and accept common aliases:

| Field | Accepted names |
|---|---|
| time | `t_us`, `time_us`, `t_ms`, `time_ms`, `t_s`, `time_s`, `seconds`, `t`, `time`, `timestamp` |
| accel | `ax`/`accel_x`/`a_x`/`acc_x`, `ay`/…, `az`/… |
| gyro | `gx`/`gyro_x`/`g_x`/`gyr_x`, `gy`/…, `gz`/… |

If no time column is present, timestamps are synthesised from the sample rate
(`--rate`, default 200 Hz). A plain `t`/`time` column is interpreted using
`--time-unit` (`us`, `ms`, or `s`; default `us`).

### Options

`to-csv`:

| Flag | Description |
|---|---|
| `--precision N` | decimal places for values (default 6) |
| `--no-derived` | omit the `accel_mag` / `gyro_mag` columns |

`to-paddle`:

| Flag | Description |
|---|---|
| `--rate HZ` | sample rate written to the header (default: from source, else 200) |
| `--arange G` | accel full-scale in g (default: from source, else 4) |
| `--grange DPS` | gyro full-scale in deg/s (default: from source, else 500) |
| `--version V` | firmware version string (default: from source, else 1) |
| `--dropped N` | dropped-sample count for the footer (default: 0) |
| `--time-unit {us,ms,s}` | unit for a plain `t`/`time` column (default: us) |
| `--precision N` | decimal places for accel (default: 4) |
| `--gyro-precision N` | decimal places for gyro (default: 2) |

Explicit flags override any metadata found in the source file.

## Tests

```bash
python3 -m unittest discover -s tools/tests -v
```

The suite covers metadata parsing, both conversion directions, a lossless
round-trip, column aliases, synthesised timestamps, malformed-row handling and
direction auto-detection. A sample recording lives in
[`tools/tests/fixtures/pm_0001.csv`](tests/fixtures/pm_0001.csv).
